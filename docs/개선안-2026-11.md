# hopbox 개선안

점검 기준: `develop` 9d5f124 (v1.0.2), 2026-11-10. 저장소는 고치지 않았다.

## 한 줄 정의

전체화면 앱을 데스크톱(Space)마다 띄워 놓고 일하는 사람이, 화면 끝에서 드래그가 끊기는 문제를 피하려고 단축키로 지금 화면에 불러 쓰는 임시 보관 상자. 한 화면에서 파일·글·이미지를 담고 다른 화면에서 다시 불러 꺼낸다.

## 컨셉·의도

- 컨셉: 택배상자. 단축키를 누르면 마우스 옆에 상자가 떨어지고, 담으면 통통 튀고, 열면 Dock 스택처럼 부채꼴로 펼쳐진다 (`README.ko.md` "택배 받는 느낌", `docs/기획서.md` 목표 표).
- 대상: 맥에서 전체화면 앱을 여러 Space 에 띄우는 사람, 윈도우에서 가상 데스크톱·전체화면 창을 오가는 사람.
- 핵심 가치 네 가지(기획서): 전체화면을 깨지 않는다 / 원본 파일은 건드리지 않는다(끌어낼 때 항상 복사) / 알아서 담되 민감한 값은 안 담는다 / 받는 느낌.
- 명시된 범위 밖: 원본 옮기기, 일반 파일 복사 보관, 기기 간 동기화, 손쉬운 사용·화면 기록 권한 요구, Linux.
- 배포: 무료, GitHub Releases. 맥은 Developer ID 서명 + 공증 dmg(로컬 `./build.sh release`), 윈도우는 서명 없는 Inno Setup 설치 파일(GitHub Actions). 수익 모델 없음.

## 구조와 스택

- 맥: Swift 5.9 Swift Package, 실행 타깃 하나(`Package.swift`), 외부 의존 없음. AppKit + SwiftUI + Carbon(단축키) + QuickLookThumbnailing + ServiceManagement.
- `AppDelegate` 가 메뉴 막대·단축키·설정을 들고, `ShelfPanel`(nonactivating `NSPanel`, `.floating`, `[.moveToActiveSpace, .fullScreenAuxiliary]`)이 `BoxView`(아이콘·알림) → `FanView`/`ShelfListView` 를 띄운다.
- 창 크기는 `BoxLayout` 이 계산하고 아이콘 자리(anchor)는 고정한다. 펼칠 때는 창을 먼저 키우고 내용을 애니메이션한다.
- `ShelfStore` 가 상태 전부: 항목 목록, 담기 규칙, 되돌리기, 알림, 저장(`~/Library/Application Support/Hopbox/items.json` + `images/`).
- 일반 파일은 경로만 저장하고, 붙여넣은 이미지·임시 폴더 파일·파일 약속으로 받은 것만 `images/` 에 복사한다.
- `ScreenCaptureWatcher` 가 폴더(DispatchSource)와 클립보드(0.5초 타이머)를 본다. `Updater` 는 GitHub API → dmg → 서명·공증 확인 → 바꿔 끼우기.
- 윈도우: C# WPF(.NET 8), 같은 구조를 `ShelfStore`(화면·클립보드를 모르는 순수 로직) + `Transfer`(형식 변환) + `BoxWindow` 로 나눴다. 맥보다 로직과 화면이 잘 분리돼 있어 시험이 붙어 있다.
- CI: `.github/workflows/windows.yml` 하나. 윈도우 시험·게시·실행 확인·설치 파일. 맥 빌드는 CI 에 없다.

### 🔴 1. 목록 파일을 못 읽으면 보관한 이미지를 전부 지운다 (맥)

- **지금 문제**: `init` 이 `load()` 뒤에 바로 `removeOrphanImages()` 를 부른다 (`ShelfStore.swift:88-89`). `load()` 는 읽기나 해석에 실패하면 아무 표시 없이 빈 목록으로 돌아온다 (`:421-425`). 그러면 `images/` 의 모든 파일이 "목록에 없는 파일"이 되어 지워진다 (`:411-417`). 그다음 담기 한 번에 `save()` 가 깨진 목록도 덮어쓴다. 재현 시험에서 잘린 JSON, 모르는 `kind` 값 두 경우 모두 지워졌다. 두 번째 경우는 나중에 항목 종류를 하나 추가한 뒤 사용자가 예전 버전으로 돌아가기만 해도 일어난다. 윈도우판은 `_loadFailed` 로 이미 막았다 (`ShelfStore.cs:37-38, 57, 345-352`).
- **고치는 방법**: 윈도우판과 같게 한다. `load()` 가 "파일이 없음"과 "읽었는데 실패"를 구분해 돌려주고, 실패하면 `items.json` 을 `items.json.<시각>.bak` 으로 복사해 두고 `removeOrphanImages()` 를 건너뛴다. 항목 단위로 해석해서 모르는 항목만 버리는 것도 같이 넣는다(`[ShelfItem]` 대신 항목마다 `try?`).
- **나아지는 점**: 붙여넣은 이미지·Slack 에서 받은 파일처럼 원본이 따로 없는 것이 목록 파일 한 번 깨졌다고 사라지지 않는다.
- **예상 결과**: 위 재현 시험 세 경우 모두 "보관 이미지 남음", 깨진 경우 `.bak` 파일 1개 생성.

### 🟠 2. 첫 실행에 데스크톱 폴더 접근 허용 창이 뜰 수 있고, 거부하면 조용히 안 된다

- **지금 문제**: 스크린샷 자동 담기 기본값이 켜짐이고 (`ScreenCaptureWatcher.swift:27`), 저장 위치를 따로 정하지 않았으면 데스크톱 폴더를 나열하고 연다 (`:88, 97, 99, 121`). macOS 는 샌드박스가 아닌 앱도 데스크톱·문서·다운로드 폴더를 읽을 때 사용자 동의를 받는다. 거부하면 `listFiles` 가 빈 배열을 돌려주고 (`:120-125`) `open` 이 실패해 그냥 돌아온다 (`:100`). 메뉴에는 여전히 체크가 켜져 보인다. README 는 "따로 허용할 권한은 없습니다"라고 적었다. 실제 창이 뜨는지는 이번에 실행해 확인하지 못했다(아래 "확인 못 한 것").
- **고치는 방법**: 폴더를 못 열면 `watchesFiles` 상태와 별개로 "지켜보지 못함" 상태를 두고, 메뉴 항목 제목을 `스크린샷 자동 담기 (폴더 접근 허용 필요)` 로 바꿔 누르면 시스템 설정 › 개인정보 보호 › 파일 및 폴더를 연다. README 의 권한 문장을 "스크린샷 자동 담기는 스크린샷 저장 폴더 접근 허용이 필요할 수 있습니다"로 고친다.
- **나아지는 점**: 자동 담기가 왜 안 되는지 사용자가 알 수 있다. README 가 실제와 맞는다.
- **예상 결과**: 접근을 거부한 계정에서 메뉴에 안내가 보이고, 허용 후 5초 안에(`:62` 의 확인 주기) 감시가 붙는다.

### 🟠 3. 자동으로 담긴 이미지가 끝없이 쌓인다

- **지금 문제**: 복사한 이미지 자동 담기도 기본값이 켜짐이다 (`ScreenCaptureWatcher.swift:27`). 이미지를 복사할 때마다 PNG 로 `images/` 에 저장하고 (`ShelfStore.swift:185-191, 282-304`) 목록 맨 앞에 넣는다. 지우는 길은 사용자가 직접 빼는 것뿐이다. 기한·개수·용량 한도가 없다. 5K 화면 캡처는 한 장에 수 MB 이므로 몇 주 쓰면 수백 MB 가 Application Support 에 남는다. 상자 숫자 배지도 계속 커져서 "방금 담은 것"을 찾는 용도가 흐려진다.
- **고치는 방법**: 항목에 `auto: Bool`(자동으로 담겼는지)을 두고, 자동 항목은 기본 7일 뒤 켤 때와 하루 한 번 정리한다. 메뉴에 "자동으로 담긴 것 보관: 1일 / 7일 / 계속" 을 둔다. 사용자가 직접 담은 것은 건드리지 않는다. 목록 머리에 보관 용량을 한 줄로 보여 준다.
- **나아지는 점**: 디스크가 조용히 차지 않는다. 상자가 "지금 옮기는 것" 중심으로 유지된다.
- **예상 결과**: 7일 넘은 자동 항목 0개, `images/` 크기가 최근 7일치로 유지.

### 🟠 4. 큰 파일 약속은 10초에 끊기고, 보내는 앱이 쓰는 중인 폴더를 지운다

- **지금 문제**: 파일 약속을 받을 때 10초 뒤 무조건 실패로 처리하고 받던 폴더를 지운다 (`ShelfStore.swift:256-261`). 사진 앱의 원본 영상, 브라우저가 내려받아야 하는 큰 이미지는 10초를 넘길 수 있다. 그때 보내는 앱은 아직 쓰는 중이다.
- **고치는 방법**: 고정 10초 대신 "받는 폴더의 크기가 10초 동안 변하지 않으면" 실패로 본다. 받는 동안 알림을 "가져오는 중…" 으로 유지하고(지금은 1.6초 뒤 사라진다, `:454`), 상자 아이콘에 진행 표시를 둔다.
- **나아지는 점**: 큰 파일도 담긴다. 받는 중인지 실패했는지 보인다.
- **예상 결과**: 1GB 영상 약속이 끝까지 받아져 담기고, 응답 없는 약속은 10초 정지 뒤 "가져오지 못했어요".

### 🟠 5. 자동 업데이트 알림이 앱을 앞으로 끌어온다

- **지금 문제**: 켠 지 10초 뒤와 하루 한 번 새 버전을 찾으면 `NSApp.activate(ignoringOtherApps: true)` 뒤 모달 알림을 띄운다 (`Updater.swift:48-55, 85-88, 128-135`). 막는 조건은 "상자가 보이는 중"뿐이다 (`AppDelegate.swift:25`). 전체화면에서 글을 쓰던 중에 포커스를 가져간다. "전체화면을 방해하지 않음"이 이 앱의 첫 번째 목표다. 윈도우판은 알림 풍선을 쓴다 (`Updater.cs:17`).
- **고치는 방법**: 자동 확인에서는 창을 띄우지 않는다. 메뉴 막대 아이콘에 점을 찍고 메뉴 항목을 "새 버전 1.0.3 설치…" 로 바꾸는 것(이미 `AppDelegate.swift:112-119` 에 있다)으로 충분하다. 다음에 상자를 부를 때 알림 자리에 "새 버전이 나왔어요" 를 한 번 보여 준다. 모달은 사용자가 메뉴를 눌렀을 때만.
- **나아지는 점**: 앱이 스스로 포커스를 뺏는 경로가 없어진다.
- **예상 결과**: 자동 확인 중 활성 앱이 바뀌지 않음.

### 🟠 6. 이미지 변환·파일 복사를 메인 스레드에서 한다

- **지금 문제**: 붙여넣은 이미지를 TIFF 로 풀고 PNG 로 다시 압축해 쓰는 일 (`ShelfStore.swift:282-304`), 눌러서 복사할 때 파일을 읽어 TIFF 와 PNG 를 둘 다 만드는 일 (`:319-331`), 임시 폴더 파일을 통째로 복사하는 일 (`:216-225`)이 모두 메인 스레드다. 클립보드 폴링 타이머도 메인에서 돈다 (`ScreenCaptureWatcher.swift:171-188`). 큰 캡처를 복사하면 그 순간 단축키를 눌러도 상자가 늦게 뜬다. 윈도우판은 가상 파일을 최대 512MB 까지 UI 스레드에서 메모리로 읽는다 (`Transfer.cs:29, 170-246`, `ShelfStore.cs:217-231`).
- **고치는 방법**: 맥은 `saveImage`·`keepCopy` 를 백그라운드 큐에서 하고 끝나면 메인에서 `insert` 한다. PNG 데이터가 이미 있으면 그대로 쓰는 지금 경로는 유지한다. 눌러서 복사는 PNG 원본이면 파일 데이터를 그대로 올리고 TIFF 는 요청받을 때 만들도록 `NSPasteboardItemDataProvider` 를 쓴다. 윈도우는 가상 파일을 스트림으로 바로 디스크에 쓴다.
- **나아지는 점**: 큰 이미지를 다루는 중에도 상자가 바로 뜬다. 윈도우는 메모리 사용이 파일 크기만큼 늘지 않는다.
- **예상 결과**: 5K 캡처 복사 직후 단축키 반응 지연이 사라짐(지금 수치는 재지 못했다).

### 🟡 7. 맥 쪽에 시험이 하나도 없고 CI 가 맥 코드를 빌드하지 않는다

- **지금 문제**: 담기 순서(파일 → 약속 → 이미지 → 글), 임시 폴더 판정 (`ShelfStore.swift:207-213`), 버전 비교 (`Updater.swift:166-174`), 창 배치 (`BoxLayout.swift:58-68`), 자동 담기 판정 (`ScreenCaptureWatcher.swift:194-201`)이 순수 함수인데 시험이 없다. 윈도우판은 같은 규칙에 시험이 27개 있다. 워크플로는 `windows/**` 가 바뀔 때만 돈다 (`windows.yml:11`). 🔴 1 이 윈도우에서는 고쳐졌는데 맥에 남은 것도 이 차이 때문으로 보인다.
- **고치는 방법**: 실행 타깃을 `HopboxCore`(라이브러리) + `Hopbox`(실행)로 나누고 `Tests/HopboxCoreTests` 를 XCTest 로 둔다. 첫 시험은 이번 재현 시험 세 경우, `isNewer` 경계값, `BoxLayout.make` 의 방향·줄 수, `isTemporary`. `macos-latest` 에서 `swift build && swift test` 를 도는 워크플로를 추가한다. `Info.plist` 버전과 태그가 같은지도 같이 본다(다르면 업데이트가 전부 실패한다, `Updater.swift:214`).
- **나아지는 점**: 윈도우에서 고친 것이 맥에 빠지는 일을 시험이 잡는다.
- **예상 결과**: `swift test` 10개 안팎 통과, PR 마다 맥 빌드 확인.

### 🟡 8. 저장 실패를 삼킨다

- **지금 문제**: `save()` 가 `try?` 로 끝난다 (`ShelfStore.swift:441-444`). 디스크가 찼거나 권한이 바뀌면 화면에는 담겼다고 나오고 다시 켜면 없다. 보관 폴더 만들기 실패도 같다 (`:87`).
- **고치는 방법**: 실패하면 "저장하지 못했어요" 알림을 띄우고 os 로그에 오류를 남긴다.
- **나아지는 점**: 재시작 뒤에 사라지는 일을 그 자리에서 안다.
- **예상 결과**: 쓰기 금지 폴더로 시험하면 알림 1회.

### 🟡 9. 모션 줄이기·VoiceOver 를 고려하지 않았다

- **지금 문제**: `accessibilityReduceMotion` 을 보는 곳이 없다(전체 검색 0건). 내려앉기·들썩임·부채꼴이 항상 돈다. 상자 아이콘과 항목은 `NSView` 덮개(`WindowHandle`, `DragSource`)가 입력을 받는데 접근성 이름·동작이 없다 (`DragSource.swift:22-113`). 키보드로는 ⌘V·⌘W·esc 만 된다 (`ShelfPanel.swift:166-190`).
- **고치는 방법**: `NSWorkspace.shared.accessibilityDisplayShouldReduceMotion` 이면 내려앉기를 0.12초 페이드로, 들썩임(`BoxView.swift:154`)을 테두리 강조로 바꾼다. `DragSourceView` 에 `setAccessibilityRole(.button)`·`setAccessibilityLabel(item.title)` 과 누르기 동작을 단다. 키보드는 기능 제안 1.
- **나아지는 점**: 모션에 민감한 사용자와 VoiceOver 사용자가 쓸 수 있다.
- **예상 결과**: 모션 줄이기를 켜면 흔들림·튀는 동작 0.

### 🟡 10. dmg 에서 바로 실행하면 업데이트 오류 문구가 알아볼 수 없다

- **지금 문제**: 앱을 응용 프로그램 폴더로 옮기지 않고 열면 macOS 가 읽기 전용 임시 경로에서 실행한다. 그때 업데이트는 "`/private/var/folders/…/AppTranslocation/…` 폴더에 쓸 수 없어요" 로 끝난다 (`Updater.swift:183-186`).
- **고치는 방법**: 경로에 `/AppTranslocation/` 이 있으면 "응용 프로그램 폴더로 옮긴 뒤 다시 열어 주세요" 로 바꾼다. 첫 실행에서 같은 조건이면 한 번 안내한다.
- **나아지는 점**: 사용자가 할 일을 안다.
- **예상 결과**: 해당 경우 안내 문구 1종.

### ⚪ 사소

- 원본이 없어진 항목은 끌어도 아무 일도 없다 (`ShelfStore.swift:341`, `DragSource.swift:43`). "원본 파일을 찾을 수 없어요" 알림을 띄운다.
- 켤 때 단축키 등록 실패 알림이 앱을 앞으로 가져오지 않고 뜬다 (`AppDelegate.swift:29-34`). 메뉴 막대 앱이라 다른 창 뒤에 깔릴 수 있다.
- 글 길이에 한도가 없다. 수십 MB 글을 담으면 담고 뺄 때마다 `items.json` 전체를 다시 쓴다 (`ShelfStore.swift:441`).
- 썸네일 캐시 열쇠가 경로뿐이라 같은 이름으로 덮어쓴 파일은 예전 그림이 보인다 (`Thumbnails.swift:9-27`). 열쇠에 수정 시각을 넣는다.
- 목록 행이 그려질 때마다 보관 파일을 `NSImage(contentsOf:)` 로 연다 (`ShelfView.swift:162`). 담을 때 한 번 판정해 항목에 저장한다.
- 맥은 다른 앱이 넘긴 파일에 격리 표시를 붙이지 않는다. 윈도우는 붙인다 (`ShelfStore.cs:237`).
- 윈도우 설치 파일에 코드 서명이 없다. 업데이트의 SHA-256 은 같은 GitHub 응답에서 오므로 전송 오류는 잡지만 계정 탈취는 못 막는다 (`Updater.cs:179-183`). 기획서 "나중" 항목.

## 기능 기획 제안

### 1. 키보드로 꺼내기 (S)

- 무엇을: 상자가 떠 있을 때 숫자 `1`~`9`, `0` 을 누르면 부채꼴의 그 줄을 복사하고 상자를 닫는다. `↑↓` 로 줄을 옮기고 `↩` 로 복사, `⌫` 로 빼기.
- 왜 맞는지: 단축키로 부르는 물건인데 부른 다음에는 마우스를 잡아야 한다. 전체화면에서 글을 쓰다가 손을 떼지 않고 `⌃⌥B` → `1` → `⌘V` 가 된다.
- 흐름: 상자 부름 → 부채꼴 줄마다 왼쪽에 작은 번호 → 숫자 누름 → "복사했어요" 뒤 0.4초에 상자 닫힘.
- 범위: `ShelfPanel.swift` `keyDown` 추가, `FanView.swift` `FanRow` 에 번호·선택 상태, `BoxState` 에 `selectedIndex`. 윈도우는 `BoxWindow.cs` `KeyDown`.

### 2. 따라오는 상자 (S)

- 무엇을: 메뉴에 "화면을 옮기면 따라오기". 켜면 Space 를 바꿨을 때 상자가 접힌 아이콘 상태로 새 화면의 같은 자리에 깡충 뛰어 들어온다.
- 왜 맞는지: 이름이 HOPBOX 이고 소개 문장이 "깡충깡충 오가는"인데, 지금은 화면을 옮기면 상자가 이전 화면에 남고 단축키를 한 번 더 눌러야 한다. 담고 → 옮기고 → 꺼내는 흐름에서 키 입력이 하나 준다.
- 흐름: 화면 A 에서 담음 → 화면 B 로 스와이프 → 0.2초 뒤 같은 자리에 상자가 뛰어 들어옴(펼치지 않음) → 눌러서 펼침.
- 범위: `ShelfPanel.swift` 에 `NSWorkspace.activeSpaceDidChangeNotification` 관찰자, 보이는 상태였을 때만 `orderOut` → `deliver()`. 설정 키 하나, `AppDelegate` 메뉴 항목 하나. 윈도우는 창이 이미 모든 가상 데스크톱에 뜨므로 연출만.

### 3. 보낸 것 표시와 "꺼내면 비우기" (S)

- 무엇을: 끌어내기가 받아들여지면 그 항목에 "보냄" 도장을 찍고 흐리게 한다. 메뉴 옵션 "꺼낸 것은 상자에서 빼기"를 켜면 5초 되돌리기와 함께 자동으로 뺀다.
- 왜 맞는지: 택배는 배달하면 상자가 빈다. 지금은 무엇을 이미 옮겼는지 표시가 없어 상자가 쌓이기만 한다.
- 흐름: 항목을 Slack 으로 끔 → 놓음 → 도장 → (옵션) "상자에서 뺐어요 · 되돌리기".
- 범위: 끌기 끝 콜백이 이미 있다 (`DragSource.swift:74-76`, `operation` 을 로그만 남김). 여기서 `store.markSent(ids)` 호출. `ShelfItem` 에 `sentAt`, `FanRow`·`ShelfRow` 표시.

### 4. 자동 담긴 것 보관 기한과 고정 (M)

- 무엇을: 🟠 3 의 정리 규칙에 더해, 항목 우클릭 "고정"으로 기한에서 빼고 맨 위에 둔다.
- 왜 맞는지: "알아서 담되 함부로 담지 않게"가 목표인데 지금은 알아서 담기만 한다. 매번 붙이는 서명 이미지·자주 쓰는 문구는 고정해 두는 쓰임이 생긴다.
- 흐름: 우클릭 → 고정 → 테이프 붙은 모양으로 맨 위. 나머지 자동 항목은 7일 뒤 사라짐.
- 범위: `ShelfItem` 에 `auto`·`pinned`, `ShelfStore` 에 정리 함수와 정렬, `DragSource.swift` `contextMenu`, `AppDelegate` 메뉴. 윈도우 `ShelfStore.cs` 동일.

### 5. 옮겨진 원본 따라가기 (M)

- 무엇을: 파일 항목에 경로와 함께 북마크 데이터를 저장하고, 원본이 이름이 바뀌거나 다른 폴더로 옮겨지면 새 위치를 찾아 쓴다.
- 왜 맞는지: "파일은 복사하지 않고 원본을 가리킨다"가 원칙이라, 원본을 정리하면 상자 항목이 "원본 파일을 찾을 수 없어요"가 된다. 특히 데스크톱의 스크린샷은 자주 옮겨진다.
- 흐름: 스크린샷이 자동으로 담김 → 사용자가 Finder 에서 폴더로 옮김 → 상자에서 끌면 새 위치의 파일이 나감.
- 범위: `ShelfItem` 에 `bookmark: Data?`, `ShelfItem.url` 을 북마크 해석 우선으로, 해석 결과가 바뀌면 `path` 갱신 후 저장. 윈도우는 대응 수단이 약해(셸 링크 추적) 맥만.

### 6. 목록에서 골라 끌어내기 (M)

- 무엇을: 목록에서 ⌘클릭·⇧클릭으로 여러 줄을 고르고 그중 하나를 끌면 고른 것만 나간다.
- 왜 맞는지: 지금은 하나 아니면 전부다 (`ShelfView.swift:53`). 스크린샷 세 장만 첨부하는 일이 가장 흔한데 세 번 끌어야 한다.
- 흐름: "그 외 N개" → ⌘클릭 3개 → 끌기 → 드래그 그림에 3 배지.
- 범위: `ShelfListView` 에 `selection: Set<UUID>`, `ShelfRow` 의 `DragSource.writers` 를 선택 기준으로, 클릭 동작(지금은 복사)과 선택의 충돌은 "⌘ 없이 클릭 = 복사, ⌘클릭 = 선택"으로 정리.

### 7. 첫 실행 배달 (S)

- 무엇을: 처음 켰을 때 화면 가운데 아래로 상자를 한 번 떨어뜨리고 "⌃⌥B 로 어디서든 불러요" 를 알림 자리에 보여 준다. 자동 담기 두 가지가 켜져 있다는 것도 여기서 한 줄로 알린다.
- 왜 맞는지: 메뉴 막대 앱이라 처음 열면 아무 일도 일어나지 않는다 (`AppDelegate.swift:21-35` 는 상자를 띄우지 않는다). 복사한 이미지가 디스크에 저장된다는 사실을 사용자가 모른 채 쓰게 된다.
- 범위: `AppDelegate` 에 첫 실행 플래그, `ShelfPanel.show(at:)`, 알림 문구 2개.

## 디자인·인터랙션 제안

비평 기준은 `impeccable` 스킬의 critique 항목(이 제품에만 맞는 디자인인가, 감정 흐름의 정점과 끝, 상태·카피·접근성)을 참고했다. 실행 화면은 보지 못했고 코드의 수치로 판단했다.

### 컨셉이 살아 있는 곳

- 내려앉기: 22pt 위에서 0.2초 easeIn 으로 떨어지고, 닿는 순간 가로 1.06·세로 0.92 로 눌렸다가 스프링(0.3, 감쇠 0.6)으로 돌아온다. 먼지 6개가 0.45초 동안 양옆으로 퍼진다 (`BoxView.swift:196-213, 180-193`). 가속해서 떨어지고 닿을 때 눌리는 순서가 맞다.
- 담김: 1.08·0.86 으로 더 깊게 눌리고 감쇠 0.4 로 더 오래 튄다. "+N" 이 32pt 올라가며 0.8초에 사라진다 (`:216-222`). 내려앉기보다 담김이 더 크게 반응하도록 차이를 둔 것이 좋다.
- 끌고 오면: 1.12 배로 커지고 ±4도를 0.14초 주기로 흔들며 열린 상자 그림으로 바뀐다 (`:116, 154, 97`).
- 창은 고정하고 그림만 움직인다는 결정(`ShelfPanel.swift:82-83`, `BoxLayout.swift:3-4`)이 모든 연출의 바탕이다. 유지한다.

### 컨셉이 빠진 곳과 바꿀 방향

1. **깡충이 없다.** 이름과 소개는 뛰는 상자인데 코드에는 떨어지는 동작만 있다. 사라질 때는 연출 없이 바로 없어진다 (`ShelfPanel.swift:97-100`). 방향: 닫을 때 0.06초 눌렸다가(0.94) 0.14초 동안 28pt 위로 뛰며 사라진다. 다른 화면에서 다시 부르면 지금의 22pt 대신 48pt 위에서 포물선으로(가로 12pt 치우쳐) 들어와 한 번 작게(6pt) 되튄다. 처음 부를 때(이전에 떠 있지 않았을 때)는 지금의 "툭 떨어짐"을 유지해 배달과 이동을 구분한다.
2. **소리가 없다.** `NSSound` 사용 0건. 택배는 소리로 기억되는 물건이다. 방향: 내려앉을 때 짧고 낮은 골판지 "툭"(80ms 안쪽), 담길 때 한 음 높은 "톡". 볼륨은 시스템 알림음의 절반, 메뉴에 "소리" 한 줄(기본 꺼짐으로 시작해도 된다). 0.5초 안에 연달아 담기면 한 번만 낸다.
3. **색이 상자에서 오지 않는다.** "+N", 끌어오기 화살표, 줄 테두리, 목록 머리 아이콘이 모두 `Color.accentColor`(시스템 파랑) 이다 (`BoxView.swift:123, 142`, `FanView.swift:126`, `ShelfView.swift:51`). 배지 빨강(0.86, 0.24, 0.2), 먼지 베이지, 메모지 노랑은 제각각 박혀 있다 (`BoxView.swift:135, 186`, `Thumbnails.swift:68`). 방향: 상자 그림에서 뽑은 골판지색·테이프색·운송장 빨강 세 가지를 `Theme` 한 곳에 두고 강조색을 테이프색으로 바꾼다. 윈도우판은 이미 `Theme.cs` 가 있다.
4. **알림·이름표·버튼이 전부 같은 모양이다.** 반투명 캡슐 + 그림자가 알림(`BoxView.swift:260`), 이름표(`FanView.swift:124-128`), "그 외 N개"(`:77`), 둥근 버튼(`:150`)에 똑같이 쓰인다. 어느 앱에나 있는 모양이라 여기가 택배상자라는 단서가 없다. 방향: 이름표를 운송장 딱지처럼 왼쪽에 종류 띠(파일·이미지·글 색 구분)가 있는 모서리 4pt 사각으로 바꾸고, 알림만 캡슐로 남긴다.
5. **목록에 들어가면 컨셉이 사라진다.** 목록은 표준 팝오버 재질, 머리의 `square.stack.3d.up.fill`, 휴지통·X 버튼, 맨 아래 도움말 한 줄이다 (`ShelfView.swift:31-33, 49, 26`). 방향: 머리 아이콘을 상자 그림 축소판으로 바꾸고, "택배상자 12" 대신 "담긴 것 12개", 맨 아래 도움말 줄은 빼고 빈 상태에서만 보여 준다(같은 안내가 부채꼴 빈 상태 `FanView.swift:54`, 목록 빈 상태 `ShelfView.swift:86-88`, 목록 바닥 세 군데에 있다).
6. **메뉴 막대 아이콘이 상태를 말하지 않는다.** 항상 `shippingbox` 다 (`AppDelegate.swift:80`). 방향: 담긴 게 있으면 `shippingbox.fill`, 담기는 순간 0.3초 동안 한 번 튄다. 상자를 부르지 않아도 자동 담기가 일했다는 것이 보인다.
7. **부채꼴 펼침은 맞지만 접힘이 밋밋하다.** 펼칠 때는 줄마다 18ms 씩 늦춰 스프링(0.38, 감쇠 0.78)으로 나온다 (`FanView.swift:47`). 접을 때는 `FanView` 가 통째로 제거되어 0.25초 뒤 창이 준다 (`ShelfPanel.swift:110-118`). 방향: 접을 때 줄을 역순으로 상자 쪽으로 빨아들이고(각 0.12초, 12ms 간격), 마지막에 상자가 한 번 작게 눌린다(0.96).
8. **문구.** 말투는 "~어요"로 일관되고 짧다. 유지한다. 고칠 곳: "복사했어요 · ⌘V 로 붙여넣기" 는 매번 나오므로 "복사했어요" 로 줄인다 (`ShelfStore.swift:333`). "담을 수 있는 내용이 없어요" 는 이유가 없다. 클립보드가 비었을 때는 "복사한 게 없어요" 로 나눈다 (`:171`). "N개 담았어요" 는 "+N" 과 겹치므로 한 개일 때는 파일 이름을 보여 준다("보고서.pdf 담았어요").
9. **윈도우판과의 연출 차이.** 윈도우는 먼지가 없고 눌림 복원이 `ElasticEase`(진동 1회, 0.45초) 한 가지다 (`BoxWindow.cs:362-367`). 맥의 내려앉기·담김 두 단계 차이를 윈도우에도 옮긴다(복원 시간 0.3초와 0.45초).

## 성능 제안

측정값은 빌드 시간뿐이다. 아래는 코드 근거가 확실한 것만 적었다.

- 클립보드를 0.5초마다 본다 (`ScreenCaptureWatcher.swift:171`). macOS 에는 변경 알림이 없어 폴링 자체는 피할 수 없다. `changeCount` 비교만 하는 지금 구조는 가볍다. 타이머에 `tolerance = 0.2` 를 주면 시스템이 깨우는 시점을 묶을 수 있다.
- 스크린샷 저장 위치를 5초마다 `CFPreferencesAppSynchronize` 로 다시 읽는다 (`:62-65, 79`). 30초로 늘리거나, 상자를 부를 때와 폴더 감시가 끊겼을 때만 확인한다.
- 폴더가 바뀔 때마다 폴더 전체를 나열한다 (`:135-143`). 데스크톱에 파일이 수천 개면 스크린샷 한 장마다 전체 나열이다. `knownFiles` 와 비교하기 전에 수정 시각이 감시 시작 이후인 것만 보도록 `contentsOfDirectory` 에 `.contentModificationDateKey` 를 미리 받는다.
- 메인 스레드 이미지 변환·복사는 🟠 6.
- 목록 행의 `NSImage(contentsOf:)`·`fileExists` 반복은 ⚪ 항목. 호버할 때마다 행이 다시 그려지므로(`ShelfView.swift:152`) 네트워크 볼륨의 파일이 담겨 있으면 목록이 버벅일 수 있다. `exists` 를 상자를 부를 때 한 번 계산해 `ShelfStore` 에 캐시한다.
- 맥 업데이트는 dmg 를 `Data(contentsOf:)` 로 통째로 메모리에 받는다 (`Updater.swift:193`). dmg 가 작아 지금은 문제없다. 시간 제한이 없으므로 `URLSession` 다운로드로 바꾸고 60초 제한을 둔다.

## 확인 못 한 것

- 앱을 실제로 띄워 보지 않았다. 설치·실행은 실행 중인 앱을 끄고 `~/Applications` 를 바꾸기 때문이다. 모션·색·겹침은 코드 수치로만 판단했다.
- 🟠 2 의 데스크톱 폴더 동의 창이 지금 macOS(Darwin 25.5)에서 실제로 뜨는지, 뜬다면 어떤 문구인지.
- macOS 의 클립보드 개인정보 보호(앱이 사용자 동작 없이 클립보드를 읽으면 알리는 기능)가 0.5초 폴링에 반응하는지. `types` 만 볼 때와 이미지 데이터를 읽을 때(`ScreenCaptureWatcher.swift:182-187`)가 다를 수 있다. 반응한다면 "복사한 이미지 자동 담기" 기본값을 꺼야 한다.
- 🟠 5 에서 전체화면 Space 위로 모달 알림이 뜰 때 Space 가 실제로 전환되는지.
- 🟠 6 의 지연 시간. 큰 이미지로 재지 않았다.
- 전체화면 앱 위에 `.floating` 레벨 패널이 항상 올라오는지(Stage Manager, 외부 모니터별 Space, 전체화면 영상). 코드 설정(`ShelfPanel.swift:26-31`)은 통상 맞는 조합이다.
- 윈도우판 전체: 빌드·시험·실행 모두 못 했다(`dotnet` 없음, WPF). `BoxWindow.cs`·`ItemActions.cs`·`Settings.cs`·`Native.cs` 는 핵심 줄만 추려 읽었고 `Tray.cs`·`ShortcutWindow.cs`·`Thumbnails.cs`·`ListCard.cs`·`FanView.cs` 는 읽지 않았다. 기능 차이표의 윈도우 쪽 "O" 중 줄번호가 없는 것은 `docs/기획서.md` 의 표를 따랐다.
- `README.md`(영문)와 `docs/설계서.md`·`구현도.md`·`결정기록.md` 본문은 읽지 않았다. 영문 README 가 한국어판과 같은지 대조하지 않았다.
- 릴리스 dmg 의 실제 서명·공증 상태(`spctl`)는 내려받아 확인하지 않았다.
- 사용자에게 물을 것: 자동 담긴 것의 기본 보관 기한(7일 제안), 소리 기본값, 윈도우 코드 서명 인증서를 살지, "따라오는 상자"를 기본으로 켤지.
