#주요 흐름

#단축키로 상자 부르기 (맥)

sequenceDiagram
  participant U as 사용자
  participant HK as HotKey (Carbon)
  participant AD as AppDelegate
  participant P as ShelfPanel (비활성 NSPanel)
  participant B as BoxView
  U->>HK: ⌃⌥B
  HK->>AD: 단축키 눌림
  AD->>P: 상자 부르기
  P->>P: 지금 보고 있는 Space로 옮김 (moveToActiveSpace)
  P->>P: 마우스 옆에 창을 놓음 (창은 움직이지 않음)
  P->>B: 그림만 위에서 내려앉기 + 먼지
  alt 담긴 게 있음
    B->>P: 저절로 부채꼴 열기
  end
  Note over P: 앱을 활성화하지 않아서 전체화면이 풀리지 않는다

#담기 (붙여넣기·끌어다 놓기)

flowchart TD
  A["클립보드 또는 드롭"] --> C{"숨김 표시?<br/>비밀번호 관리자 값"}
  C -- 예 --> X["담지 않음"]
  C -- 아니오 --> F{"파일 URL?"}
  F -- 예 --> T{"임시 폴더 파일?"}
  T -- 예 --> IMG["상자 images/로 복사<br/>kind = image"]
  T -- 아니오 --> FILE["원본 경로만 기록<br/>kind = file"]
  F -- 아니오 --> PR{"파일 약속<br/>file promise?"}
  PR -- 예 --> W["파일이 써질 때까지 기다려 images/에 받음"] --> IMG
  PR -- 아니오 --> I{"이미지 데이터?<br/>png · tiff · jpeg · gif · heic · webp"}
  I -- 예 --> IMG
  I -- 아니오 --> TXT["글로 담기<br/>kind = text"]
  IMG --> S["items.json 저장 · +N 연출"]
  FILE --> S
  TXT --> S
  • 브라우저는 이미지와 주소 글자를 같이 올리므로 글자보다 이미지를 먼저 본다. 실제 판단 순서는 ShelfStore.swift 참고.

#업데이트 (맥)

sequenceDiagram
  participant A as 앱
  participant GH as GitHub API
  participant U as 사용자
  A->>GH: releases/latest (켤 때, 하루 한 번)
  GH-->>A: 버전, 이 맥에 맞는 dmg
  A->>U: 새 버전 알림 (같은 버전은 저절로 한 번만)
  U->>A: 업데이트
  A->>A: dmg 받기 → 서명 팀 · 공증 · 번들 ID · 버전 확인
  A->>A: 앱 바꿔 끼우기 (실패하면 원래 앱 되돌림)
  A->>A: 지금 앱이 끝난 뒤 새 앱 켜기

#핵심 파일

파일 설명
Sources/Hopbox/ShelfPanel.swift .nonactivatingPanel, .fullScreenAuxiliary. 항목 위에서는 창 끌기(배경 잡아 옮기기)를 끄고 상자 아이콘에서만 창이 움직이게 했다
Sources/Hopbox/BoxLayout.swift 아이콘은 늘 같은 화면 자리(anchor), 창은 펼친 내용만큼 그 둘레로 커진다. 창 크기를 먼저 바꾸고 화면을 나중에 바꾼다
Sources/Hopbox/ShelfStore.swift 담기 판단, 임시 파일 보관, 5초 되돌리기(undoSeconds), 고아 이미지 정리
Sources/Hopbox/ScreenCaptureWatcher.swift com.apple.screencapture location 따라가기, 클립보드 0.5초 확인
Sources/Hopbox/Shortcut.swift 기본 ⌃⌥B, 허용 조합 검사, 한글 입력 중에도 영문 자판 기준 키 이름
Sources/Hopbox/Updater.swift 맥 업데이트
windows/Hopbox.Windows/BoxWindow.cs 창 크기는 늘 같고 투명 부분은 클릭이 지나간다. 아이콘을 화면 안으로 당기고 펼칠 방향을 정한다
windows/Hopbox.Windows/Transfer.cs 가상 파일(실제 크기로 자르기, 크기 상한, 이름 걸러내기, 인터넷 표시), DIB 읽기
windows/Hopbox.Windows/Updater.cs 24시간마다 확인, digest sha256 비교, /VERYSILENT 설치
.github/workflows/windows.yml 시험 → x64·arm64 단일 실행 파일 → 켜서 상자 부르기 시험 → 설치 파일 → 태그면 릴리스에 붙이기

#빌드·실행·배포

#맥

swift build             # 디버그 빌드
./build.sh              # build/택배상자.app
./build.sh install      # ~/Applications 에 설치하고 실행
./build.sh release      # build/release/Hopbox-macOS-{apple-silicon,intel}.dmg
# SIGN_IDENTITY="Developer ID Application: ..." NOTARY_PROFILE=<notarytool 프로필> ./build.sh release
  • Xcode 없이 Command Line Tools만 있으면 된다.
  • 서명 값이 없으면 임시 서명(codesign --sign -)만 하고 공증은 건너뛴다.

#윈도우

dotnet test windows/Hopbox.Windows.Tests      # 시험
dotnet run --project windows/Hopbox.Windows   # 실행
  • 설치 파일은 GitHub Actions가 만든다. windows/**가 바뀐 push마다 돌고, v* 태그면 같은 이름의 릴리스에 Hopbox-Windows-{x64,arm64}-Setup.exe를 붙인다(릴리스가 없으면 초안 생성).

#릴리스 순서 (히스토리에서 본 방식)

  1. Resources/Info.plist의 버전을 올리는 커밋.
  2. vX.Y.Z 태그 → 윈도우 설치 파일은 Actions가 붙인다.
  3. 맥 dmg는 ./build.sh release(서명·공증)로 만들어 같은 릴리스에 올린다.
  4. 릴리스 파일 이름에 버전을 넣지 않는다. README의 releases/latest/download/ 링크가 늘 최신을 가리킨다.
  • 원격에는 release/v1.0.0, release/v1.0.1, release/v1.0.2, feature/windows 브랜치가 남아 있다. develop 브랜치는 2026-11-05 문서 작업 때 main에서 처음 만들었다.
